## 0. Where things stand right now

+ The **GitHub repo (`main`) is the main version.** 
    Neocities serves as it's mirror domain,
        therefore the two are always synonymous.
-   **local/ `pecweb` is the phsyical SSD root source, which also mirrors.
- Nothing flows from Neocities back to GitHub. Neocities is an output, not a source.

Keep in mind:
> GitHub `main` is the master copy. Your PC holds a working copy you edit and push.
> Neocities and GitHub Pages are published copies.

## 2. The pieces

```
★-| Piece                                        | Runs where                     | Starts when                                      | What it does.

★-| Git + Git Bash                               | your PC                        | you type a command                               | Tracks changes; sends them to GitHub and fetches them back.
★-| GitHub repo                                  | github.com                     | --------                                         | Stores every file and the full history.
★-| GitHub Pages                                 | GitHub                         | `main` changes                                   | Publishes the repo's top folder at the github.io address.
★-| Workflow `.github/workflows/neocities.yml`   | GitHub's servers               | any push to `main`, or the "Run workflow" button | Builds the log, commits it back, deploys to Neocities.
★-| `scripts/build_log.py`                       | inside the workflow (Python 3) | step 1 of the workflow                           | Rebuilds the log from `log-entries/`.                     
★-| `js/site.js`, `js/lang-pt.js`, `js/hit.js`   | the visitor's browser          | page load                                        | Theme and language buttons, Portuguese text, click areas. Not part of any pipeline.
```


### What the workflow does, step by step 

1. **Checkout.** Gets the repo's files.
2. **Build log** (`python3 scripts/build_log.py`, marked `continue-on-error`).
   + Reads every `.md` / `.txt` note in `log-entries/`, newest first.
   + Rewrites what sits between `<!-- LOG:START -->` and `<!-- LOG:END -->` in `sitemap.html`.
   + Rewrites what sits between `/* LOG:START */` and `/* LOG:END */` in `js/lang-pt.js`.
   + sets the footer "Last updated" date on every page to today (Belo Horizonte time) **Only if the log changed,** 
   + Running it twice changes nothing the second time.
   + If it fails, the error shows as red under Annotations and the deploy still happens.
3. **Commit rebuilt files.** Stages `*.html` and `js/lang-pt.js`. If anything changed, it
   commits as `github-actions[bot]` with the message `Rebuild log from log-entries [skip ci]`,
   runs `git pull --rebase`, and pushes to `main`. A commit made this way does not start
   another run, which is why the deploy happens in the same run.
4. **Collect site files** into a temporary `dist/` folder: `index.html`, `sitemap.html`,
   `wiki.html`, `css/style.css`, `js/site.js`, `js/hit.js`, `js/lang-pt.js`, `sonoro/`,
   `masks/`, and `robots.txt` if it exists.
5. **Deploy to Neocities** with the stored secret `NEOCITIES_API_TOKEN`, `cleanup: false`.




### What is not deployed to Neocities

`scripts/`, `log-entries/`, `.github/`, `.gitignore`, `list of git commands.txt`,
`images/`, the unused Bootstrap files, and this sheet.




### The note format (for `log-entries/`)

File name: `YYYY-MM-DD-short-slug.txt` (or `.md`), for example `2026-10-19-first-note.txt`.


Short title

English paragraph. Links work like [this](https://example.com).

Another English paragraph.

---pt---
Titulo curto

Paragrafo em portugues. Links: [isto](https://example.com).

Outro paragrafo em portugues.


- The Portuguese part is optional. Anything missing stays in English.
- A file whose name does not look like `YYYY-MM-DD-slug.md/.txt` is skipped with a yellow
  warning (this includes `.gitkeep.txt`).
> Never edit between the `LOG:START` / `LOG:END` markers by hand. The next build overwrites it.

## 3. Which route do I use? ( ╹ -╹)?
```
★-| I want to...                                | Use                                             | Notes.
```

## 4. Route A - commit directly on GitHub (website or phone)

### A1. Add, edit or delete a log note
    
1. On the repo page open `log-entries/` (type `log-entries/` in the file name when creating
   a file if the folder is gone; GitHub creates it).
2. Create a new file named like `2026-10-19-my-note.txt`, or open an existing one.
3. Write the note in the format above.
4. Commit **directly to the `main` branch** (not "create a new branch").

What happens next, in about a minute:

1. The workflow starts.
2. The build script rewrites the log in `sitemap.html` and `js/lang-pt.js`, and sets every
   page's footer date.
3. The bot commits those files back to `main`.
4. The site files are uploaded to Neocities.
5. GitHub Pages republishes `main`.

To delete an entry, delete the note file and commit. The log rebuilds without it.

### A2. Edit any other file on GitHub

Open the file, change it, commit to `main`. The workflow script runs the build
step finds nothing to change; the deploy uploads the changed files.
Footer dates do **not** change by themselves for ordinary page edits - edit the date in the
footer in the same commit.

### After any Route A commit

- **Your local folder is now behind GitHub.** The bot adds a commit too.
- Before you edit anything locally, run `git pull`.
- Check the **Actions** tab: a green check means it deployed.








## 5. Route B - commit from Git Bash in your local `pecweb` folder

### B0. Start of every session

```
cd "/path/to/pecweb"    - alternatively you can type "cd " and drag your root folder in as well.
                        - if you're on Windows you can also right click in your root folder and launch Git Bash from there.
git status -sb          # shows "behind N" if GitHub has newer commits.
git pull                # bring them down BEFORE you edit anything.
```

### B1. The standard flow

```
git pull                           # 1. latest from GitHub first
                                   # 2. edit your files
git status                         # 3. see what changed
git add .                          # 4. stage everything
git commit -m "what I changed"     # 5. snapshot with a note
git push                           # 6. upload; both sites update
```

If you edited a page, update its footer date in the same commit.

### B2. What happens after your push

1. GitHub receives the commit and starts the workflow.
2. The build step runs. If you did not touch `log-entries/`, it changes nothing.
3. The deploy uploads your changed files to Neocities. GitHub Pages republishes.
4. If the build did change something (you added a note), the bot makes a new commit on
   GitHub. **Your local folder is behind again; `git pull` before your next edit.**

### B3. `git pull` refuses: "Your local changes would be overwritten"

Git is protecting your uncommitted edits to a file that GitHub also changed.

```
Pull blocked
 |
 +-- The listed files are edits you MADE ON PURPOSE and want to keep
 |      git add <files>
 |      git commit -m "my edits"
 |      git pull            (if Git reports a conflict, see below)
 |
 +-- The listed files are unwanted or damaged local changes
 |      cp <file> ../<file>.backup      (safety copy first)
 |      git restore <file>
 |      git pull
 |
 +-- Not sure
        git diff <file>                 (read the changes)
        or:  git stash  ->  git pull  ->  git stash pop
```

A conflict looks like `<<<<<<< HEAD` ... `=======` ... `>>>>>>>` inside a file. 
Open the file,
keep the version you want, delete the three marker lines, 
then `git add .` and `git commit`.


### B4. `git push` is rejected ("fetch first" / "remote contains work you do not have")

GitHub has a newer commit than you (often the bot's). 
Run `git pull`, then `git push` again.
If an editor window opens asking for a merge message, save and close it.

### B5. Notes from Git Bash (batch)

Save your note files into `log-entries/` with the right names, then:

```
git pull
git status
git add .
git commit -m "notes"
git push
```

All the notes in that commit publish together; the log is rebuilt once. You do not need to run
`build_log.py` yourself.

### Local-only habits

- Edit `js/lang-pt.js` only in an editor set to **UTF-8 without BOM**. Saving it as ANSI turns
  the symbols into `?` and breaks the Portuguese text.
- If you run `python3 scripts/build_log.py` locally to test, it edits `sitemap.html`,
  `js/lang-pt.js` and footer dates. The bot will make the same edits on GitHub, so do not
  commit local build results unless you mean to.







## 6. Route C - edit directly on Neocities

**There is no pipeline from Neocities back to GitHub.** None has been written. Anything you
change in the Neocities dashboard or upload there exists only on Neocities.

What can happen to a hand edit on Neocities (verify):
```
★-| What you did on Neocities                    | What happens at the next deploy |

★-| Edited a file that the workflow deploys      | It can be **overwritten** by the repo's version, because the deploy action re-uploads files whose contents differ.
★-| Uploaded a file the workflow does not deploy | It stays, because `cleanup` is `false`.
★-| Deleted a file that the workflow deploys     | It is re-uploaded at the next deploy.
```
If you did edit something on Neocities and want to keep it:

1. Download or copy the file's content from Neocities.
2. Put it into the same path in your local `pecweb` folder.
3. `git pull`, `git add .`, `git commit`, `git push` (Route B).

>**avoid editing deployed files on Neocities directly.** Preferably Use Routes A or B.






## 7. Bring your local folder in line with GitHub (one time)

Use this when GitHub is the version you want and your local copy is behind or damaged.

```
cd "/path/to/pecweb"
git status -sb                       # what differs right now
git diff > ../local-changes.patch    # safety copy of uncommitted edits to tracked files
git fetch origin                     # download GitHub's latest; touches none of your files
git reset --hard origin/main         # tracked files become identical to GitHub
git status -sb                       # expect:  ## main...origin/main  and nothing else
```

- `git reset --hard` **discards uncommitted edits to tracked files.** That is why the patch is
  saved first. If there is a file you made only locally and want to keep, copy it out first.
- It does not touch untracked or ignored files (audio, `.psd`, `_notes/`).
- Any `??` lines left in `git status` are untracked files. Delete them or ignore them.
- Gentler alternative: `git restore <file>` on the specific files, then `git pull`.

## 8. Command reference
-----------------------------------------------
```
★-| Command                        | What it does.

★-| `cd "/path/to/pecweb"`         | Go to the site folder. Quotes are needed if the path has spaces.
★-| `pwd`                          | Print the folder you are in.
★-| `ls`                           | List files (lowercase L).
★-| `git status`                   | Show changed files and the branch. Add `-sb` for the short version.
★-| `git diff`                     | Show line-by-line changes in files you have not staged. `q` leaves the viewer.
★-| `git diff <file>`              | Same, for one file.
★-| `git log --oneline -10`        | The last 10 commits, one line each.
★-| `git fetch origin`             | Download GitHub's latest without changing your files.
★-| `git pull`                     | Fetch and merge GitHub's latest into your folder. Always do this first.
★-| `git add .`                    | Stage every change for the next commit (space, then dot).
★-| `git add <file>`               | Stage one file.
★-| `git commit -m "note"`         | Save a snapshot of what is staged, with a short note.
★-| `git push`                     | Upload your commits to GitHub; this triggers the deploy.
★-| `git restore <file>`           | Throw away your uncommitted edits to a file. Cannot be undone .
★-| `git restore --staged <file>`  | Unstage a file; keeps your edits.
★-| `git stash` / `git stash pop`  | Set your edits aside / bring them back.
★-| `git reset --hard origin/main` | Make tracked files identical to GitHub. Destroys uncommitted edits.
★-| `git ls-files`                 | List every tracked file.
★-| `git remote -v`                | Show which GitHub repo this folder is connected to.
★-| `git config --global --list`   | Show your saved Git settings.
★-| `git clone <url>`              | Copy the repo onto a new computer.
★-| `grep -rn "^<<<<<<<..." .`     | Find leftover merge-conflict markers (see B3).
★-| `python3 scripts/build_log.py` | Rebuild the log locally. Normally you never need it.
```

## 9. Troubleshooting

some common issues i've run into here n there and tips+remedies that have proved helpful, 
```

★----------------------------------Symptom ----------------------> Likely cause(s) ----------------------------> Fix 

★-|-`git pull` blocked: "local changes would be overwritten" -----> You have uncommitted edits to a file GitHub also changed  ---------> refer to B3* 
★-|---------------------- `git push` rejected: "fetch first" -----> GitHub has a newer commit (often the bot's)  ---------> `git pull`, then `git push` 
★-|------------------------An editor opens during `git pull` -----> Git wants a merge message  ---------> Save and close it 
★-|-------------- `<<<<<<< HEAD` text on a page or in a file -----> Merge-conflict markers were committed or left  ---------> `grep` check in B3; fix; commit
★-|-------Accents turn into `?` or odd symbols in Portuguese -----> `js/lang-pt.js` saved in the wrong encoding  ---------> `git restore js/lang-pt.js`, `git pull`; edit only in UTF-8
★-|---------------------------------New note does not appear -----> Wrong file name, empty note, or it was committed to another branch  ---------> Check the name (`YYYY-MM-DD-slug.txt`), commit to `main`, read the build step in Actions.
★-|---Yellow warning "Skipped '...': name must look like..." -----> A file in `log-entries/` is not a dated note (for example `.gitkeep.txt`)  ---------> Rename it, delete it, or ignore the warning.
★-|--------------Red X on "Build log" but the site deployed  -----> The build script failed; the deploy continues by design  ---------> Open the run, read the error under Annotations.
★-|--------------------------Red X on "Deploy to Neocities"  -----> Secret missing or mistyped, or Neocities is down  ---------> Check the run log; re-run with "Run workflow".
★-|-----------------------Site looks unchanged after a push  -----> Browser cache, or the run has not finished  ---------> Wait for the green check; private tab or Ctrl+Shift+R .
★-|---------Footer date did not change on a page you edited  -----> The script only changes dates when the log changes  ---------> Edit the footer date yourself.
★-|----------------------------Local folder says "behind N"  -----> GitHub has commits you do not (phone edits, bot commits) ---------> `git pull`.
```
